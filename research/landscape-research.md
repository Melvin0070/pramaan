# AI agents for vulnerability triage & remediation — landscape as of 2026-09-02

Scope note: everything below was checked against a live source; where a page was unreachable it is flagged. "Vendor-reported" means the number comes from the company selling the tool; treat those as marketing until reproduced.

## 0. The short version (where the whitespace is)

- Detection is commoditising fast (Mythos, Codex Security, CodeMender, XBOW, AISLE), but **verification, prioritisation with business context, and safe remediation are the bottleneck** — Anthropic itself says the "relative ease of finding vulnerabilities compared with the difficulty of fixing them amounts to a major challenge" ([Help Net Security, Glasswing update, 2026-05-26](https://www.helpnetsecurity.com/2026/05/26/anthropic-project-glasswing-update/)).
- Almost no vendor publishes precision/recall against public ground truth; agreement between AI scanners on the same code was 5% and a single scanner reproduced only 17% of its own findings across runs ([Contrast Security via Help Net Security, 2026-08-31](https://www.helpnetsecurity.com/2026/08/31/contrast-security-ai-appsec-tools-security-findings-report/)). A project that ships **reproducible evals with published confusion matrices and kappa against human labels** is differentiated on day one.
- Every shipping tool draws the same autonomy line: agents propose, humans apply (Claude Code Security, CodeMender, Codex Security, Copilot Autofix). The interesting design question — which senior engineers will probe — is *how* you decide when to auto-close a finding vs. escalate, and how you prove that decision is calibrated (Semgrep's asymmetric design, Torq's confidence-gated autonomy, THOR's asymmetric cost matrix are the closest published patterns).
- Prompt injection through PR titles/issue bodies has already compromised the exact class of agent you'd build (Anthropic's own action, Cline's triage bot). Treating scanner output and ticket text as untrusted, with deterministic pre/post checks and least-privilege tool surfaces, is table stakes, not a nice-to-have.

### 1.2 GitHub Copilot Autofix
- GA since 2024: CodeQL alert → LLM-generated fix suggestion. GitHub's beta data (May–Jul 2024): median 28 min to commit a fix vs 1.5 h manual; >2/3 of alerts remediated "with little or no editing" across JS/TS/Java/Python ([GitHub blog](https://github.blog/news-insights/product-news/secure-code-more-than-three-times-faster-with-copilot-autofix/)).
- Security campaigns (bulk backlog + Autofix) are GA ([discussion](https://github.com/orgs/community/discussions/155613)); alerts can be assigned to Copilot ([changelog 2025-10-28](https://github.blog/changelog/2025-10-28-assign-code-scanning-alerts-to-copilot-for-automated-fixes-in-public-preview/)); **agentic autofix** public preview 2026-07-09: explores the repo, runs CodeQL + LLM detectors + linters on its own fix, iterates, opens a *draft* PR in 2–4 min ([discussion](https://github.com/orgs/community/discussions/201446)).
- GitHub's responsible-use doc is unusually candid: non-deterministic; may emit syntactically wrong, mis-located, or semantically wrong fixes; may fail to remediate or introduce new vulns; may suggest "fabricated dependencies published under statistically probable names"; evaluated on an internal harness of 2,300+ public-repo alerts with test coverage, but no pass rate is published ([docs](https://docs.github.com/en/code-security/responsible-use/responsible-use-autofix-code-scanning)).

### 1.3 Semgrep Assistant (Memories, triage, autofix)
- Autotriage recommends dismissals with reasoning; noise filtering claimed >95% accurate at labelling FPs; Memories are per-project/per-rule context snippets that humans approve; autofix opens PRs; fallback between OpenAI (primary) and Bedrock; auto-analysis only for Critical/High severity, High/Medium confidence findings ([docs](https://docs.semgrep.dev/semgrep-assistant/overview)).
- Methodology behind the 96% claim: Semgrep researchers hand-triaged 2,000+ findings; Assistant started at ~55% agreement; final result is 96% agreement *on true positives* and 41% on FPs; the model only sees "several dozen lines" around the finding ([Semgrep blog](https://semgrep.dev/blog/2025/building-an-appsec-ai-that-security-researchers-agree-with-96-of-the-time/)). Design choice worth copying: **asymmetric classification** — separate prompt chains for "confidently FP → act" vs "TP → add context", never a zero-sum binary ([60% triage post](https://semgrep.dev/blog/2025/semgrep-is-confidently-handling-60-of-all-triage-for-users-without-reducing-coverage/), [Memories launch](https://semgrep.dev/blog/2025/announcing-ai-noise-filtering-and-triage-memories/)).

### 1.11 Triage-methodology standards
- **SSVC**: decision points Exploitation (none / PoC / active), Automatable, Technical Impact, mission/well-being; CISA's tree yields Track / Track* / Attend / Act ([SEI SSVC docs](https://certcc.github.io/SSVC/)). Deployer trees produce defer / scheduled / out-of-cycle / immediate — a good target label set for an agent.
- **CVSS 4.0** (Nov 2023): Base/Threat/Environmental/Supplemental groups, Attack Requirements metric ([Qualys](https://blog.qualys.com/product-tech/2023/11/02/cvss-v4-is-now-live-and-what-do-you-need-to-know)).
- **EPSS v4** (2025-03-17): at matched ~74.6% coverage, "CVSS ≥ 7" costs 50.7% effort at 6% efficiency vs EPSS 6% effort at 47% efficiency ([Empirical Security](https://research.empiricalsecurity.com/research/introducing-epss-version-4)).
- **CISA KEV**: consensus first gate before EPSS/SSVC ([Picus comparison](https://www.picussecurity.com/resource/blog/comparing-cvss-epss-kev-ssvc-lev-and-pxs-from-scores-to-security-proof)).
- **Reachability**: function-level reachability across transitive deps ([Endor docs](https://docs.endorlabs.com/scan/sca/reachability-analysis), [Semgrep](https://semgrep.dev/blog/2025/what-you-should-know-about-dependency-reachability-in-sca/)).
- Context: NVD stopped universal enrichment in April 2026 with a 27,000+ backlog and 48,185 CVEs in 2025 ([NIST](https://www.nist.gov/news-events/news/2026/04/nist-updates-nvd-operations-address-record-cve-growth)).

## 2. What senior practitioners complain about (concrete pain points)

1. **Nondeterminism and near-zero cross-tool agreement.** Contrast ran three AI scanners on one 2M-LOC codebase: they agreed on 5% of findings; one scanner reproduced only 17% of its own findings across runs; scanning cost ~$315 in API fees but triaging the output ~$128,000 ([Help Net Security](https://www.helpnetsecurity.com/2026/08/31/contrast-security-ai-appsec-tools-security-findings-report/)). Vendors admit it ([GitHub](https://docs.github.com/en/code-security/responsible-use/responsible-use-autofix-code-scanning), [Anthropic](https://code.claude.com/docs/en/claude-security)). Implication: any triage agent needs pass^k-style consistency evals, not single-run demos.
2. **Signal-to-noise / speculative findings.** "20 highly speculative reasons why code is problematic along with one critical error" ([HN](https://news.ycombinator.com/item?id=46766961)); "if 7 out of 8 flagged items are fine, people ignore warnings" ([HN](https://news.ycombinator.com/item?id=49240431)).
3. **FP filtering that silently suppresses true positives.** Agentic FP filters remove 93–95% of SAST noise but "aggressive FP reduction suppresses true vulnerabilities" ([Sifting the Noise, arXiv 2601.22952](https://arxiv.org/abs/2601.22952)); QASecClaw: 88.6% FP cut with 3.1% recall loss ([arXiv 2605.01885](https://arxiv.org/abs/2605.01885)). Florian Roth's THOR triage benchmark penalises TP→FP suppression at −4.0 ([Medium](https://cyb3rops.medium.com/why-i-built-my-own-llm-benchmark-for-thor-finding-triage-c8492e3997dc), [GitHub](https://github.com/Nextron-Labs/thor-ai-benchmarks)). Nobody reports the miss rate — that is the number a security engineer will ask for.
4. **Discovery outruns remediation; maintainers are the bottleneck.** Glasswing update names maintainers as the constraint; Stenberg's "High-Quality Chaos": report volume doubled again in 2026, confirmed-vuln rate 15–16% ([daniel.haxx.se](https://daniel.haxx.se/blog/2026/04/22/high-quality-chaos/)); Linux kernel security list "almost entirely unmanageable" ([Help Net Security](https://www.helpnetsecurity.com/2026/05/18/problems-with-ai-assisted-vulnerability-research/)). Triage/dedup/ownership assignment is where the value is.
5. **AI slop reports and bounty collapse.** curl: ~5% valid, ~20% AI slop by mid-2025; bounty ended 2026-01-31 ([BleepingComputer](https://www.bleepingcomputer.com/news/security/curl-ending-bug-bounty-program-after-flood-of-ai-slop-reports/)); "AI-DDoS" study: one-time contributors' merge rate fell 18.18% ([arXiv 2607.04003](https://arxiv.org/abs/2607.04003)). Stenberg's checklist for a good report (human-written summary, stand-alone reproducer, patch, version bisection) is a ready-made rubric for grading agent-generated tickets ([daniel.haxx.se](https://daniel.haxx.se/blog/2026/06/29/do-excellent-vulnerability-reports/)).
6. **Fake CVEs and untrustworthy severity data.** JFrog found 54 bogus CVEs from one repo ([The Register](https://www.theregister.com/security/2026/08/03/ai-slop-pollutes-the-cve-pipeline-with-fake-vulns/5282462)); NVD scored curl's CVE-2020-19909 9.8 for an integer overflow in a retry delay ([daniel.haxx.se](https://daniel.haxx.se/blog/2023/08/26/cve-2020-19909-is-everything-that-is-wrong-with-cves/)); Mythos reported five "confirmed" curl vulns, curl kept one low-severity CVE ([daniel.haxx.se](https://daniel.haxx.se/blog/2026/05/11/mythos-finds-a-curl-vulnerability/)). An agent that copies NVD CVSS into "severity" without its own reasoning will be dinged.
7. **Fixes that compile but don't fix (or break things).** AutoPatchBench: ~60% of LLM patches compiled and stopped the crash, but only 5–11% survived fuzzing + differential testing; "cheating patches" suppress crashes without fixing root causes; Meta's own verifier had 41.7% precision ([Meta Engineering](https://engineering.fb.com/2025/04/29/ai-research/autopatchbench-benchmark-ai-powered-security-fixes/)). SEC-bench: best agent patched 34% ([arXiv 2506.11791](https://arxiv.org/abs/2506.11791)). The "fake fix" that passes visible tests is the central risk ([arXiv 2603.01257](https://arxiv.org/html/2603.01257v1)).
8. **Prompt injection through the data the agent must read.** "Comment and Control": Anthropic's security-review action interpolated the PR title into the prompt unsanitised; a crafted title made Claude run `whoami`/`ps` and post `ANTHROPIC_API_KEY` and `GITHUB_TOKEN` as a "finding" ([oddguan.com](https://oddguan.com/blog/comment-and-control-prompt-injection-credential-theft-claude-code-gemini-cli-github-copilot/), [SecurityWeek](https://www.securityweek.com/claude-code-gemini-cli-github-copilot-agents-vulnerable-to-prompt-injection-via-comments/)). "Clinejection" (Feb 2026): Cline's `claude-issue-triage.yml` ran claude-code-action with Bash for any GitHub user; an issue title led to cache poisoning and a tampered npm CLI on ~4,000 machines ([Adnan Khan](https://adnanthekhan.com/posts/clinejection/), [Cline post-mortem](https://cline.bot/blog/post-mortem-unauthorized-cline-cli-npm)). CamoLeak (CVSS 9.6): hidden markdown comments hijacked Copilot Chat ([Legit Security](https://www.legitsecurity.com/blog/camoleak-critical-github-copilot-vulnerability-leaks-private-source-code)). Your inputs (SARIF, DAST reports, SIEM alerts, ticket text, repo CLAUDE.md files) are attacker-influenced by construction.
9. **No business context.** "severity describes potential impact, but it does not establish whether vulnerable code is reachable… what mitigating controls already exist, or how important the affected application is" ([Checkmarx](https://checkmarx.com/blog/four-appsec-imperatives-from-black-hat-usa-2026/)); Pixee's "is the risk already accepted?" check is one of the few explicit business-context steps.
10. **Unverifiable vendor numbers / no evals.** Google disclosed no FP rates ([TechInformed](https://techinformed.com/googles-soc-agent-cuts-alert-review-from-30-minutes-to-60-seconds/)); Pixee's 76% and Semgrep's 96% are agreement/merge rates, not precision/recall on public data. Elastic's rule — "No tool call, no credit… capped at 6/10" — exists because "the most dangerous failure mode… is the confident, fluent, wrong answer that was never grounded in a tool call" ([Elastic Security Labs](https://www.elastic.co/security-labs/llm-benchmarking-agentic-soc)).
11. **Cost and latency at scale.** Anthropic Code Review averages $15–25 per PR review and ~20 minutes ([docs](https://code.claude.com/docs/en/code-review)); Contrast's $128k triage estimate above.

## 4. Eval + guardrail frameworks and implementable patterns

### 4.1 Frameworks
- **Inspect AI (UK AISI)**: dataset → Task → Solver → Scorer; Docker sandboxes for tool-executing agents ([inspect.aisi.org.uk](https://inspect.aisi.org.uk/)).
- **promptfoo**: OSS evals + red-team (50+ attack plugins, prompt-injection/jailbreak), CI-friendly JSON output, has a Claude Agent SDK provider; acquired by OpenAI 2026-03-09 but staying open source ([promptfoo blog](https://www.promptfoo.dev/blog/promptfoo-joining-openai/), [red-team config](https://www.promptfoo.dev/docs/red-team/configuration/), [SDK provider](https://www.promptfoo.dev/docs/providers/claude-agent-sdk/)).
- **DeepEval** (pytest-native), **Braintrust**, **LangSmith** ([comparison](https://technspire.com/en/blog/agent-evaluation-2026-deepeval-promptfoo-langsmith)).

### 4.2 Anthropic guidance (concrete bits to reuse)
- *Building effective agents*: prefer workflows (prompt chaining with programmatic gates, routing, parallel voting, evaluator–optimizer) over open-ended agents ([Anthropic](https://www.anthropic.com/engineering/building-effective-agents)).
- *Writing tools for agents*: namespacing, high-signal returns, actionable errors, tool-level evals ([Anthropic](https://www.anthropic.com/engineering/writing-tools-for-agents)).
- *Building agents with the Claude Agent SDK*: gather context → act → verify; rules-based verification is "the best form of feedback", LLM-as-judge last ([claude.com](https://claude.com/blog/building-agents-with-the-claude-agent-sdk)).
- *Context engineering*: compaction, structured note files, sub-agents with clean context returning condensed summaries ([Anthropic](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)).
- *Effective harnesses for long-running agents*: initializer vs worker agent, JSON feature list initially all "failing", progress file, mandatory end-to-end test before marking done ([Anthropic](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)).
- *A harness for every task* (dynamic workflows): failure modes = agentic laziness, self-preferential bias, goal drift; patterns = classify-and-act, fan-out-and-synthesize, adversarial verification, generate-and-filter, tournament, loop-until-done ([claude.com](https://claude.com/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code)).
- *Demystifying evals for AI agents* (Jan 2026): task/trial/grader vocabulary; grade **state**, not tool-call sequences; pass@k vs pass^k; start with 20–50 tasks from real failures; balanced positive/negative cases; regression suites near 100% vs capability suites; calibrate LLM judges to humans, give judges an "Unknown" option, one judge per dimension ([Anthropic](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)).
- *CISO's guide to agentic AI*: four questions (what untrusted content? what actions/identity? blast radius? observability?) and seven controls: IdP-issued agent identity, connector allowlists, per-tool verb removal, sandboxed execution with credentials injected by proxy, egress allowlisting, OpenTelemetry of every tool call to the SIEM, org-wide kill switch ([claude.com](https://claude.com/blog/ciso-guide-to-agentic-ai)).
- *How Anthropic secures its SDLC*: shadow mode for new automated reviewers, risk-weighted sampling of automated approvals, risk-tiered codebases ([claude.com](https://claude.com/blog/how-anthropic-secures-its-ai-native-software-development-lifecycle)).

### 4.3 Claude Code / Agent SDK primitives (the enforcement layer)
- **Hooks**: `PreToolUse` (allow/deny/ask, `updatedInput`, `additionalContext`), `PostToolUse` (`updatedToolOutput` to sanitise tool output before the model sees it), `PostToolUseFailure`, `UserPromptSubmit`, `Stop`, `SubagentStart/Stop`, `PreCompact`, `PermissionRequest`, `Notification`; hook deny applies even in `bypassPermissions` ([hooks reference](https://code.claude.com/docs/en/hooks), [SDK hooks](https://code.claude.com/docs/en/agent-sdk/hooks)).
- **Permission evaluation order**: hooks → deny rules → ask rules → mode → allow rules → `can_use_tool`; `allowed_tools` does *not* constrain `bypassPermissions`; the locked-down recipe is `allowed_tools` + `permission_mode="dontAsk"` ([SDK permissions](https://code.claude.com/docs/en/agent-sdk/permissions)).
- **Permission modes**: `default`, `acceptEdits`, `plan`, `auto` (classifier model; tool results stripped from what it sees), `dontAsk`, `bypassPermissions` ([permission modes](https://code.claude.com/docs/en/permission-modes)).
- **Sandboxing**: Seatbelt (macOS) / bubblewrap (Linux); filesystem allow/deny; network egress through a proxy with `allowedDomains`; credential masking ([sandboxing](https://code.claude.com/docs/en/sandboxing), [security](https://code.claude.com/docs/en/security)).
- **Subagents**: `tools` allowlist / `disallowedTools`, `permissionMode`, `maxTurns`, `hooks`, `isolation: worktree`, fresh context per run ([sub-agents](https://code.claude.com/docs/en/sub-agents)). **Skills**: `allowed-tools`, `context: fork`, `disable-model-invocation`, `paths` ([skills](https://code.claude.com/docs/en/skills)).
- **Structured outputs** GA: `output_config.format` with JSON Schema; `strict: true` tools ([docs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)); Agent SDK `output_format={"type":"json_schema", ...}` → `ResultMessage.structured_output`.

### 4.4 Threat/risk frameworks to cite in a design doc
- OWASP Top 10 for LLM Apps 2025 — LLM01 prompt injection, LLM05 improper output handling, LLM06 excessive agency, LLM10 unbounded consumption ([OWASP](https://genai.owasp.org/resource/owasp-top-10-for-llm-applications-2025/)).
- OWASP Top 10 for Agentic Applications 2026: ASI01 goal hijack, ASI02 tool misuse, ASI03 identity/privilege abuse, ASI04 agentic supply chain, ASI05 unexpected code execution, ASI06 memory/context poisoning, ASI07 insecure inter-agent comms, ASI08 cascading failures, ASI09 human-agent trust exploitation, ASI10 rogue agents ([OWASP](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/)).
- MITRE ATLAS (agent techniques such as AML.T0098 "AI Agent Tool Credential Harvesting", AML.T0099 "AI Agent Tool Data Poisoning") ([atlas.mitre.org](https://atlas.mitre.org/)); NIST AI RMF + AI Agent Standards Initiative (2026-02-17) ([NIST](https://www.nist.gov/news-events/news/2026/02/announcing-ai-agent-standards-initiative-interoperable-and-secure)).

### 4.5 Implementable pattern checklist
1. **Schema-validated outputs**: every verdict is a strict JSON object (verdict ∈ {TP, FP, needs-human}, SSVC decision, CWE, evidence `file:line`, confidence); reject/route anything that fails validation.
2. **Deterministic pre/post checks around the model**: pattern checks before the model; tests/rescan/linters after the patch (security-guidance plugin layers; GitHub agentic autofix; CodeMender's stack).
3. **Asymmetric autonomy**: auto-close only high-confidence FPs; never auto-downgrade a TP without a human; score misses at 4× the cost of extra review (Semgrep asymmetric chains; THOR matrix; Torq gating).
4. **Permission tiers**: read-only triage agent (`dontAsk` + allowlist), patch agent in a worktree sandbox with no network except allowlisted hosts, ticketing agent whose "delete/close/assign" verbs are removed unless a human gate passes.
5. **Human-in-the-loop gates that show raw actions**: draft PRs never auto-applied; show the exact diff/ticket payload, not a summary (ASI09 mitigation).
6. **Budget/loop limits**: `max_turns` per subagent, per-hour caps, cost ceilings, circuit breakers (ASI08).
7. **Audit trail**: log every tool call via `PostToolUse` hooks to JSONL/OTel, stamp reports with commit SHA + model + effort, emit SARIF.
8. **Prompt-injection defences**: never interpolate ticket/PR/scanner strings into the system prompt; pass them as delimited data; sanitise via `PostToolUse` `updatedToolOutput`; verifier model never sees raw tool output; allowlist-only tools (no `Bash` for triage); short-lived scoped tokens; treat "instructions" found in findings as a finding themselves; red-team with promptfoo.
9. **LLM-as-judge with rubrics, calibrated**: one judge per dimension, "Unknown" option, "no tool call, no credit"; report Cohen's κ (2 raters) or Krippendorff's α (3+) against 200–500 human-labelled findings; κ < 0.4 ambiguous rubric, ≥ 0.6 acceptable, ≥ 0.8 production-ready; use κ not raw agreement because FP-heavy data inflates raw agreement.
10. **Regression suites in CI**: freeze a labelled set, run N trials per task and report pass^k, fail the build on TP→FP suppression above a threshold; keep a separate harder capability suite.
